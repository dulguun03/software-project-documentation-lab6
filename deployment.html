GitLab CI and Pages¶

The supplied URL is a GitHub repository. GitHub does not execute .gitlab-ci.yml. Import or push this source to a GitLab project to satisfy the lab’s GitLab deployment requirement.

The verification job runs tests, coverage checks, doctests and a strict HTML build on branch pushes and merge requests. Only the default branch publishes public through the modern job-level pages.publish setting. A verification failure blocks deployment. The existing Swagger and Redoc files remain in public alongside the new Sphinx reference.

After pushing, validate the configuration in GitLab’s CI Lint, wait for a green pipeline, then open Deploy > Pages and copy the actual URL into GITLAB_PUBLISH.md. Do not infer the URL from a username: GitLab can assign a unique Pages domain. Check it in a signed-out browser if public access is required. Pages hosts static reference files, not the Python sandbox.
