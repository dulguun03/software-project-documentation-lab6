Python API reference¶

Scope¶

All locally declared public classes, functions and methods in server.py and the shared samples/client.py transport are included. Constructors are included in their class reference. Inherited standard-library methods are outside this project’s authored API. Test helpers, build scripts, configuration, and executable-only sample modules are internal tools, not supported imports. The sample modules send HTTP requests at import time, so autodoc imports only their shared client. Vendored Swagger JavaScript belongs to its upstream API.

Sandbox server¶

Serve the local Sprint 06 API documentation and simulated assistant endpoints.

The sandbox inherits Python’s threaded HTTP server and serves the public directory for GET requests. POST requests use a fixed local bearer token and operate on in-memory fixtures. Calendar actions follow proposal, confirmation, and execution states; execution records a simulated provider write. No Google calls, real OAuth, AI inference, external webhook delivery, or persistence occur. Restarting the process clears all action and history state.

Examples

Validate the session identifier used throughout the documentation:

>>> fields({"session_id": "session_anu_01"}, ["session_id"])
>>> text_fields({"session_id": "session_anu_01"}, ["session_id"])

class server.SandboxServer(address)[source]¶

Host the HTTP sandbox and its shared, in-memory action state.

Construction binds and activates a listening socket through http.server.ThreadingHTTPServer; it does not start the serving loop. Call serve_forever() to accept requests and server_close() to release the socket. POST handlers serialize their work with lock.

Require a dictionary with exactly the specified field names.

Values are not inspected. Call text_fields separately to validate string content where needed.

Parameters:

server.text_fields(payload, names)[source]¶

Require each selected field to contain a nonempty string.

Whitespace is used only to detect empty content; original values are not trimmed or otherwise changed. This helper assumes the fields already exist, normally after a successful call to fields.

Parameters:

  • payload (dict[str, object]) – Request object containing the named fields.

  • names (list[str] | tuple[str, …]) – Keys whose values must be strings with at least one non-whitespace character.

Returns:

None – Successful validation leaves all field values unchanged.

Raises:

  • RequestError – With status 400 if a selected value is not a string or contains only whitespace.

  • KeyError – If a selected field is missing from the payload.

  • TypeError – If the supplied payload or field-name collection cannot support the expected iteration and dictionary lookup operations.

Examples

>>> payload = {"session_id": "session_anu_01", "title": "Sprint 06 review"}
>>> fields(payload, ["session_id", "title"])
>>> text_fields(payload, ["session_id", "title"])
>>> payload["title"]
'Sprint 06 review'

parse_body()[source]¶

Validate the declared body size and decode the previously read bytes.

do_POST must first populate request_bytes. This helper does not read from rfile or verify that the actual byte count equals the declared length. It accepts JSON for ordinary paths and multipart form data for the photo and bark-audio upload paths, and sets a ten-second timeout on the connection.

Returns:

object – Decoded JSON value of any JSON type, or a multipart field dictionary. Multipart text values are UTF-8 strings; file values are dictionaries containing basename filename, MIME content_type, and raw data bytes. Endpoint-specific object and field validation occurs later in dispatch.

Raises:

  • RequestError – With 400 for absent/invalid declared lengths, malformed JSON or multipart structure, or duplicate multipart fields; 413 for a declared length over LIMIT; or 415 for an unsupported content type.

  • UnicodeError – If a multipart text field cannot be decoded as UTF-8.

  • OSError – If setting the connection timeout fails.

  • AttributeError – If required handler state such as request_bytes has not been initialized.

Examples

Decode a history request using an inert handler and mocked socket:

>>> from unittest.mock import Mock
>>> handler = Handler.__new__(Handler)
>>> handler.path = "/v1/sessions/history"
>>> handler.request_bytes = b'{"session_id": "session_anu_01"}'
>>> handler.headers = {"Content-Length": str(len(handler.request_bytes)), "Content-Type": "application/json"}
>>> handler.connection = Mock()
>>> handler.parse_body()
{'session_id': 'session_anu_01'}
do_POST()[source]¶

Authenticate, parse, dispatch, and respond to one sandbox POST request.

The server lock protects correlation numbering and endpoint state for the complete operation. Request reads are capped at LIMIT + 1 bytes. Authorization must be Bearer `` followed by ``TOKEN; a missing or invalid value produces 401. The optional X-Sandbox-Failure header simulates 403, 500, or 503 before dispatch. RequestError becomes its specified HTTP error response; field/JSON type errors become 400 and other processing exceptions become 500.

Returns:

None – Writes one JSON response when the connection remains usable.

Raises:

  • OSError – If writing an error response also fails, for example after a client disconnect. Errors while sending the normal response first trigger an attempted 500 response.

  • AttributeError – If the handler lacks server lock/counter state needed before entering its exception-handling block.

Examples

Capture a response using in-memory request data and test doubles:

>>> from io import BytesIO
>>> from types import SimpleNamespace
>>> from unittest.mock import Mock
>>> handler = Handler.__new__(Handler)
>>> handler.server = SimpleNamespace(lock=threading.Lock(), sequence=0, history={})
>>> handler.path = "/v1/sessions/history"
>>> raw = b'{"session_id": "session_anu_01"}'
>>> handler.headers = {"Content-Length": str(len(raw)), "Content-Type": "application/json", "Authorization": "Bearer " + TOKEN}
>>> handler.rfile, handler.connection = BytesIO(raw), Mock()
>>> handler.send_json = Mock()
>>> handler.do_POST()
>>> code, response = handler.send_json.call_args.args
>>> code, response["status"], response["items"]
(200, 'succeeded', [])
dispatch(payload)[source]¶

Execute the endpoint selected by path against sandbox fixtures.

Calendar requests propose actions; confirmation requires the matching session and payload version. Execution requires confirmation and is idempotent once successful: retries preserve one history record and one simulated provider write. Other routes search fixture contacts, read session history, inspect fixture uploads, or return a simulated webhook subscription. No route invokes an external provider.

Authentication and locking belong to do_POST; callers using this helper directly must supply initialized server state and coordinate any concurrent access themselves.

Parameters:

payload (dict[str, object]) – Parsed endpoint request. Commands need exactly session_id, transcript, intent, and event; the supported intent is calendar.create. Its event needs title, timezone-aware ISO start/end with end after start, and timezone equal to Asia/Ulaanbaatar. Action confirmation/execution need session_id and positive integer payload_version. Other routes enforce their own exact field sets. Uploads use the file dictionaries from parse_body.

Returns:

tuple[int, dict[str, object]] – HTTP status and JSON response object. Successful responses use 200, except webhook subscription creation uses 201. Command/action, contact, and history results include the common envelope; upload and subscription results have their endpoint-specific fields.

Raises:

  • RequestError – With 400 for request validation failures, 404 for unknown endpoints/resources/session actions, 409 for action version/state conflicts, or 415 for invalid upload fixture types/signatures.

  • ValueError – If a datetime or callback URL cannot be parsed.

  • KeyError – If an upload dictionary lacks an accessed metadata field.

  • TypeError – If nested upload data has an incompatible value type.

  • AttributeError – If upload data lacks the expected byte operations, or required handler/server state has not been initialized.

Examples

Propose, confirm, and execute an action entirely in memory. Repeating execution does not duplicate the simulated provider write:

>>> from types import SimpleNamespace
>>> handler = Handler.__new__(Handler)
>>> handler.server = SimpleNamespace(actions={}, history={}, provider_calls=0)
>>> handler.correlation = "corr_sandbox_0001"
>>> handler.path = "/v1/commands"
>>> payload = {
...     "session_id": "session_anu_01",
...     "transcript": "Create Sprint 06 review at 10:00 in Ulaanbaatar.",
...     "intent": "calendar.create",
...     "event": {"title": "Sprint 06 review", "start": "2026-10-12T10:00+08:00",
...               "end": "2026-10-12T10:30+08:00", "timezone": "Asia/Ulaanbaatar"},
... }
>>> code, proposal = handler.dispatch(payload)
>>> code, proposal["action_id"], proposal["status"]
(200, 'action_0001', 'proposed')
>>> action_request = {"session_id": "session_anu_01", "payload_version": 1}
>>> handler.path = "/v1/actions/action_0001/confirm"
>>> code, result = handler.dispatch(action_request)
>>> result["status"]
'confirmed'
>>> handler.path = "/v1/actions/action_0001/execute"
>>> code, result = handler.dispatch(action_request)
>>> code, result = handler.dispatch(action_request)
>>> result["status"], handler.server.provider_calls, len(handler.server.history["session_anu_01"])
('succeeded', 1, 1)

Sample transport¶

Send JSON and multipart requests for the executable Sprint 06 samples.

The public API consists of post() and multipart_file(). Importing this module reads configuration but does not contact the sandbox. The default token is a public credential for the local teaching sandbox only. Set API_BASE_URL and API_AUTH_TOKEN before import to override the defaults.

client.AUTH_TOKEN = 'sprint05-local-sandbox'¶

client.post(path, payload=None, *, body=None, content_type='application/json')[source]¶

POST a request, print its status and JSON response, and return the JSON.

A non-None body takes priority over payload, including empty bytes. Otherwise payload is JSON-encoded as UTF-8, even when a different content type is supplied. The request uses the configured bearer token and a ten-second urlopen timeout. Response schemas are not validated here. HTTP errors propagate before a success record can be printed.

Parameters:

  • path (str) – Endpoint suffix beginning with /, for example /pets/upload-photo. Appended directly to BASE_URL.

  • payload (object | None) – JSON-serializable request value. Defaults to None, which sends JSON null when no raw body is provided.

  • body (bytes | None) – Optional already-encoded request body, such as the multipart bytes returned by multipart_file().

  • content_type (str) – Value of the request’s Content-Type header. Defaults to application/json; use the generated multipart content type when sending a file.

Returns:

object – Decoded response JSON, normally a dict for the sandbox endpoints. The return value does not contain the HTTP status. A JSON record with http_status and body is also printed to stdout.

Raises:

  • TypeError – If payload cannot be JSON-serialized and no body is provided.

  • ValueError – If JSON serialization finds a circular reference, or the configured URL is invalid.

  • urllib.error.HTTPError – If the server returns an HTTP error, including validation, authentication, and unsupported-media responses.

  • urllib.error.URLError – If opening the URL fails, including connection failures. The underlying cause is available as reason.

  • TimeoutError – If a socket operation reaches its timeout.

  • OSError – If a response read or stdout write fails.

  • json.JSONDecodeError – If the response is not valid JSON.

  • UnicodeDecodeError – If response bytes cannot be decoded as JSON text.

  • UnicodeEncodeError – If stdout cannot represent the printed response.

Examples

Upload the included Einstein PNG using a mocked response. This example reads the local fixture and performs no network requests:

>>> import client
>>> import io
>>> import json
>>> from contextlib import redirect_stdout
>>> from pathlib import Path
>>> from unittest.mock import patch
>>> photo = Path(client.__file__).resolve().parents[1] / "assets" / "einstein.png"
>>> data, media_type = client.multipart_file(
...     "photo", photo, "image/png", {"pet_id": "corgi_98231"})
>>> expected = {"pet_id": "corgi_98231", "photo_id": "photo_0001",
...             "filename": "einstein.png", "bytes_received": photo.stat().st_size}
>>> response = io.BytesIO(json.dumps(expected).encode("utf-8"))
>>> response.status = 200
>>> output = io.StringIO()
>>> with patch("client.urlopen", return_value=response) as transport:
...     with redirect_stdout(output):
...         result = client.post("/pets/upload-photo", body=data, content_type=media_type)
>>> result == expected
True
>>> json.loads(output.getvalue())["http_status"]
200
>>> transport.call_args.args[0].data == data
True
client.multipart_file(field_name, file_path, media_type, fields)[source]¶

Build a multipart body containing text fields and one complete file.

Text fields retain mapping iteration order and use their string representations. The file follows those fields, and the body ends with a closing boundary. The entire file and body are held in memory. The fixed boundary and unescaped field names, values, and filename are intended for the controlled lab fixtures; this helper does not validate them.

Parameters:

  • field_name (str) – Form field for the file, such as photo or audio.

  • file_path (pathlib.Path) – Local file to read. Its name property is used as the multipart filename.

  • media_type (str) – File-part Content-Type, for example image/png or audio/wav. Copied into the body without validation.

  • fields (Mapping[str, object]) – Additional text form fields, such as {"pet_id": "corgi_98231"}; each value is formatted as text.

Returns:

tuple[bytes, str] – Complete request body and matching multipart Content-Type header, including the boundary parameter. Pass these as body and content_type to post().

Raises:

  • FileNotFoundError – If file_path does not exist.

  • PermissionError – If the file cannot be read with current permissions.

  • OSError – If another filesystem error prevents reading the file.

  • UnicodeEncodeError – If a field or filename contains text that cannot be encoded as UTF-8.

Examples

Build a Corg.ly Einstein photo request without contacting a server:

>>> import client
>>> from pathlib import Path
>>> photo = Path(client.__file__).resolve().parents[1] / "assets" / "einstein.png"
>>> data, media_type = client.multipart_file(
...     "photo", photo, "image/png", {"pet_id": "corgi_98231"})
>>> media_type
'multipart/form-data; boundary=Sprint05MultipartBoundary91'
>>> b'name="pet_id"\r\n\r\ncorgi_98231' in data
True
>>> b'name="photo"; filename="einstein.png"' in data
True
>>> photo.read_bytes() in data
True
